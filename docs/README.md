# Verivo Documentation

The `docs/` directory is the durable knowledge base for the Verivo product. Documentation is organized by domain so that product intent, design rationale, engineering decisions, and supporting research remain easy to find and maintain.

## Structure

- `canon/` — accepted product truths that define Verivo and govern downstream work.
- `brand/` — brand strategy, voice, identity, and messaging guidance.
- `product/` — product strategy, requirements, specifications, and roadmaps.
- `design/` — experience principles, interaction patterns, flows, and design-system guidance.
- `growth/` — acquisition, activation, retention, experimentation, and measurement plans.
- `engineering/` — architecture, interfaces, operational guidance, and technical standards.
- `research/` — user, market, domain, and technical research with sources and findings.

Material cross-functional decisions belong in `../decisions/`. When a decision changes an accepted product truth, the corresponding Canon document must also be updated.

## Documentation expectations

Documents should state their purpose, owner, status, and last meaningful update when those details are known. Prefer links to a single authoritative source over duplicated content. Update documentation in the same change that alters the behavior or decision it describes.
