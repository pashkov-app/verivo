# Contributing to Verivo

Verivo treats documentation as part of the product. Every important product decision must become a version-controlled document so that the reasoning, trade-offs, and resulting product behavior remain discoverable over time.

## Before implementation

For any material product decision:

1. Create or update a document in the relevant area of `docs/` or in `decisions/`.
2. Record the context, decision, considered alternatives, consequences, owner, and status.
3. Obtain the appropriate review before treating the decision as accepted.
4. Link the decision document from the implementation change.
5. Update `docs/canon/` when the decision changes an accepted product truth.

Do not leave consequential decisions only in meetings, chat threads, issue comments, or pull-request discussions.

## Pull requests

Keep changes focused and reviewable. A pull request should explain why the change is needed, identify the documents it adds or updates, and call out any unresolved questions or follow-up work.

Documentation and implementation must agree. If they diverge, the change is not complete.
