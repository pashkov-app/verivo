# Verivo Canon

## UA

Canon — авторитетний запис ухвалених продуктових істин Verivo. Він визначає сталі принципи, поняття, межі та рішення, яких мають дотримуватися продуктова, дизайн-, growth- та інженерна робота.

### Як працює Canon

Кожен Canon-документ використовує стабільний ідентифікатор `VC-NNN`. Canon-документи зберігаються у системі контролю версій, проходять перегляд і змінюються свідомо. Пропозиція не є частиною Canon, доки відповідальні власники не схвалять її, а відповідний Canon-документ не буде додано або оновлено.

Коли нові докази вимагають зміни, потрібно зберегти історію в Git і явно сформулювати нову істину. Не можна мовчки переосмислювати наявне формулювання. Якщо один Canon-документ замінює інший, цей зв’язок потрібно чітко позначити та додати посилання на обидва документи.

Похідні документи можуть пояснювати або реалізовувати Canon, але не повинні йому суперечити. Якщо виникає конфлікт, Canon має перевагу, доки затверджена зміна не оновить авторитетний запис.

### Життєвий цикл документа

1. Підготувати чернетку запропонованого доповнення або зміни.
2. Перевірити докази, наслідки та конфлікти з наявним Canon.
3. Зафіксувати схвалення та об’єднати авторитетне формулювання.
4. Оновити пов’язані продуктові, дизайн-, growth- та інженерні документи.
5. Явно позначити заміну, коли ухвалена істина змінюється.

## EN

Canon is the authoritative record of Verivo's accepted product truths. It defines the durable principles, definitions, boundaries, and decisions that product, design, growth, and engineering work must follow.

### How Canon works

Each Canon document uses a stable `VC-NNN` identifier. Canon documents are version controlled, reviewed, and changed deliberately. A proposal is not Canon until the appropriate owners accept it and the relevant Canon document is added or updated.

When new evidence requires a change, preserve the history in Git and make the new truth explicit. Do not silently reinterpret existing language. If one Canon document replaces another, mark the relationship clearly and link both documents.

Downstream documents may explain or implement Canon, but they must not contradict it. When a conflict exists, Canon governs until an approved change updates the authoritative record.

### Document lifecycle

1. Draft the proposed addition or change.
2. Review its evidence, implications, and conflicts with existing Canon.
3. Record approval and merge the authoritative wording.
4. Update affected product, design, growth, and engineering documents.
5. Supersede explicitly when an accepted truth changes.
